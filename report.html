오케스트레이션 패턴 3가지

① Direct Dispatch — 단일 에이전트 라우팅

태스크 타입을 읽어 정해진 에이전트에게 위임. O(1) 라우팅 테이블.

const result = await orchestrator.dispatch({
  type: 'CREATE_TODO',
  payload: { title: 'Fix critical login bug', priority: 'high' }
});
// → TaskAgent.handle() → store.createTodo()

② Parallel Fan-out — 병렬 실행

독립적인 여러 태스크를 Promise.all()로 동시에 실행. 지연 최소화.

const [stats, topN] = await orchestrator.parallel([
  { type: 'GET_STATS',  payload: {} },          // AnalyticsAgent
  { type: 'GET_TOP_N', payload: { n: 3 } },   // PriorityAgent
]);
// 두 에이전트가 동시에 실행 → 결과를 배열로 반환
Orchestrator
⇒
AnalyticsAgent
PriorityAgent
⇒
[result1, result2]

③ Pipeline — 순차 체이닝

이전 결과를 다음 태스크 입력으로 전달하는 데이터 흐름 파이프라인.

await orchestrator.pipeline([
  () => ({ type: 'LIST_TODOS',    payload: { status: 'pending' } }),
  (prev) => ({ type: 'COMPLETE_TODO', payload: { id: prev.result.todos[0].id } }),
]);
// Step1: TaskAgent → 목록 조회
// Step2: TaskAgent → 첫 번째 항목 완료 처리 (이전 결과 사용)
LIST_TODOS
→
prev.result
→
COMPLETE_TODO

④ NLP 자연어 파이프라인

자연어 입력을 NLPAgent가 분석하고 오케스트레이터가 적합한 에이전트에게 라우팅.

await orchestrator.handleNaturalLanguage('Add urgent task: prepare demo slides');
// NLPAgent: intent=CREATE_TODO, priority=high, title='prepare demo slides'
// → Orchestrator builds structured task
// → TaskAgent executes CREATE_TODO

PriorityAgent — 자동 점수 계산 로직

제목·설명 키워드와 마감일을 조합해 수치 점수를 산정, 3단계 레이블로 변환합니다.

신호가중치예시
키워드: urgent / critical+10"ASAP: fix critical bug"
키워드: release+7"prepare release notes"
키워드: deadline+8"project deadline review"
키워드: bug / fix+5"fix login bug"
기존 priority=high+5—
마감 < 24시간+15내일 마감
마감 < 3일+8이번 주 마감
마감 < 7일+4다음 주 마감
기존 priority=low-3—
score ≥ 10 → high
score 4–9 → medium
score < 4 → low

핵심 설계 결정

싱글턴 에이전트

각 에이전트는 모듈 수준 싱글턴으로 exports됩니다. 오케스트레이터는 라우팅 테이블에 인스턴스를 직접 보유하므로 인스턴스 생성 오버헤드가 없습니다.

공유 스토어 패턴

TodoStore는 싱글턴 인메모리 상태입니다. 모든 에이전트가 동일한 참조를 공유하므로 메시지 직렬화 없이 일관된 뷰를 보장합니다.

BaseAgent 공통 인터페이스

handle(task)가 표준 래퍼로 실행 로그·에러 처리를 통일합니다. 서브클래스는 _process()만 구현하면 됩니다.

타입 기반 라우팅

오케스트레이터의 ROUTING 맵은 태스크 타입 → 에이전트 매핑입니다. 새 에이전트 추가 시 맵에 엔트리만 추가하면 됩니다.
